# A 股交易成本正则化组合

[返回 Wiki](README.md)

## 生产范围

2026-10-30 接入桌面 `jobs.market_monitor`、详情分析及 `backend.server` 的 A 股 Direct/HTTP 路径，默认模型为 `ashare_transaction_cost_regularized_v1`。行为因子的评分、资格门、前四成员、周日计算和下一交易日 09:30 激活机制保持原样，改动的是仓位分配与调仓执行。港股时空动量和 20 日目标冻结不变。Android Chaquopy 本地引擎未移植 CVXPY，仍使用原单股逻辑；访问此后端的远程分析才会读取新计划。

原先每只股票分别优化，再用卖出评分与 5 个百分点免交易带筛选，可能让目标外持仓长期占用现金。新模型在同一预算里同时决定所有目标仓位与现金，前四以外的 A 股目标强制为零，不再要求技术止损或止盈触发才允许退出。

## 数学模型

借鉴 Hautsch & Voigt 的交易成本与模型不确定性正则化思想，使用本项目已有行为因子预期收益，不复刻论文预测模型：

- [论文 DOI](https://doi.org/10.1016/j.jeconom.2019.04.028)
- [arXiv 1709.06296](https://arxiv.org/abs/1709.06296)

设 `w0` 为当前 A 股市值占账户净值比例，`w` 为目标权重，`c` 为现金，`k` 为估计成本占比：

```text
maximize mu' w - gamma/2 * w' Sigma w
         - k - beta/2 * ||w - w0||_2^2

k >= (fee_rate + slippage_rate) * ||w - w0||_1
w >= 0
w_i <= selected_i * 0.35 * (1 - k)
sum(w) + c = B - k
c >= reserve_feasible * (1 - k)
sum(w) <= max(0, 0.95 - fixed_weight) * (1 - k)
```

`B` 只包含当前 A 股市值与实际可用现金；港股市值、港股未交收款作为固定部分，不当作可花的现金。净值使用行情与账本实际股数，不使用成本仓位反推。前四之外 `selected_i=0`，目标必须归零。空前四的有效因子结果对应退出 A 股并持有现金。

`reserve_feasible = min(reserve, (B - exit_cost)/(1 - exit_cost))`，`exit_cost = 0.0018 * sum(w0)`。港股及待交收款锁定后，可达现金可能低于 5%/35%；此时仅将 A 股退出并保留能取得的现金，不为凑现金底线擅自卖港股，也不因遗漏清仓费用让问题无解。

线性成本产生有数学依据的免交易区，二次项抑制大幅换手；没有旧的固定 5 个百分点免交易带。凸问题由 CLARABEL 求解，要求最优状态且约束残差不超过 `1e-6`，否则停止交易。

## 冻结参数

| 参数 | 值 | 含义 |
|---|---:|---|
| `gamma` | 2 | 风险厌恶系数 |
| `beta` | 0.02 | 二次换手惩罚 |
| 协方差窗口 | 126 个完整交易日日收益 | 不含当日未收盘数据 |
| 对角收缩 | 20% | `0.8 * covariance + 0.2 * diagonal` |
| 风险/收益周期 | 5 个交易日 | 日协方差乘 5；20 日预期收益乘 `5/20` |
| 预期收益截断 | 20 日 ±15% | 防止极端校准值主导配置 |
| 单边费率 | 0.13% | 研究时冻结的成本假设 |
| 单边滑点 | 0.05% | 研究时冻结的成本假设 |
| 最低费用预留 | 每笔 5 元 | 整手执行预算的保守附加预留 |
| 单股/风险仓位上限 | 35% / 95% | 按完整账户净值约束 |
| 主动盈利/现金回收现金底线 | 5% / 35% | 执行时使用建计划时净值预留 |

`gamma` 使用评估期之前的校准样本选择，`beta` 等参数沿用预先冻结值。它们不是理论全局最优，也不是针对当前持仓重新搜出的最优参数。仓位是给定预测与这些约束下的数值最优解；预测误差、成本变化和样本偏差仍会影响收益。

最低费用没有以整数变量放进凸目标；整数手执行使用 `买入金额 * (1 + 0.0018) + 5` 预留，较 `max(5, 金额 * 0.0013) + 滑点` 保守。模型中的成本用于优化与现金预算，现有真实/影子账本成交记账仍按录入成交价与股数计算，不新增虚构的券商费用流水，实盘净收益应以券商成交费用核对。

生产协方差使用数据提供层的复权收盘收益；此前离线回测另做过除权/现金分红账本处理。两种数据口径在除权附近可能有细微差异，不能将历史回测收益当作实际账户将获得的收益。

风险日线读取显式要求 `required_through=最后完整交易日`；即使原历史缓存仍在宽松有效期内，也必须补齐该日才允许新建计划。行情接口的 `as_of_date` 为排他截点，组合传入完整交易日次日，并再次在协方差层截断，避免少算一天或混入未完成日线。

## 计划与执行

```text
build_behavioral_factor_context -> 激活的前四成员与20日收益估计
prepare_account_plan -> 真实/影子账户独立联合优化 -> 冻结目标股数
backend.run_committee_direct -> 从计划和账本读取剩余股数
监控提醒/影子执行/桌面记账 -> 再核对现金、成交、T+1、手数和涨跌停
```

计划按 XSHG 下一有效交易日所属周及因子目标版本冻结。同周内日度评分刷新、添加未入选关注股、修正现金和程序重启都不会重建已完成的买单。新周、正式因子目标版本改变或切换交易模式时重新求解；假期用交易日历，不按自然日推迟激活。

- 前四之外的旧 A 股产生清仓剩余单，包括可卖零股；不会因为仍盈利或单股预期收益为正而无限保留。
- 前四之内买卖按整百股取整；科创板首次买入至少 200 股。
- 先处理卖出，再检查买入，但真实账户不会预支尚未成交的卖出款。用户录入卖出成交后，下一轮才使用到账现金。
- 每笔实际成交按账本单调递增 ID 消耗计划剩余数量；部分成交只保留余量。反向成交取消该标的剩余单，导入/公司行动造成无成交流水的股数变化也取消对应旧单。
- 手动卖掉已经完成买单的标的，同周不自动买回；这是冻结订单规则，不是单独禁止当天买回。下个正式计划可重新产生买单。
- 持久化锁串行化影子执行与桌面计划记账，阻止两个进程重复使用同一余单。桌面旧卡片确认前重新核对计划版本和剩余量。
- 买入仍受新建仓右侧趋势闸门、涨停、实际现金和手数约束；卖出受 T+1、可卖股数、跌停和有效报价约束。休市仅展示等待，不自动执行影子交易。
- 新计划不再经过旧单股卖出效用评分、LLM仓位折扣或反向交易价格线冷却。LLM 显式启用时可解释与提示风险，不能用浮亏保护改写组合清仓。
- 因子、所需历史、价格、状态或求解器失败时返回 `WAIT`，不静默回退旧算法。新加入但未入选的低样本关注股不会阻塞已有可靠前四。

盘中新闻在单个后台线程刷新，监控只读取已完成的新闻缓存，不等待抓取、板块龙头提炼或新闻风险处理。首次启动缓存未就绪时，交易分析继续执行；关闭新闻刷新后不再发起新抓取。缓存按监控间隔更新，刷新期间最多沿用一小时内的上一批新闻。

监控在逐只分析前、慢分析返回后以及最终生成提醒前检查报价时效，过期时重新取价，并以当前时间、真实账本和原计划剩余股数复核数量与金额。新建仓仍受原趋势闸门约束；报价刷新不会重建目标或恢复已完成订单。真实账户决策日志与桌面快照使用最终复核结果。报价默认最多有效 180 秒（`INVEST_INTRADAY_QUOTE_MAX_AGE_SECONDS`），刷新失败、仍过期、时间异常、T+1 或跌停时继续等待，不能通过修改报价时间戳绕过保护。

## 本地状态与接口

`data/ashare_allocation_state.json` 按 `real` / `committee` 保存 `revision`、`created_at`、`data_as_of`、`effective_at`、交易模式、协方差参数、目标/剩余股数、成交游标。文件及备份含账户派生信息，必须 Git ignored，不能公开上传。

响应与监控行新增 `portfolio_optimizer`：`model`、`account`、`plan_revision`、`verdict`、`units`、`alloc_cny`、`target_weight_pct`、`remaining_units`、`reason`、`effective_at`、`data_as_of`。请求中的组合建议只能暂停，不能覆盖账本生成可执行订单。`behavioral_factor.target_weight_pct` 仍是因子参考权重，桌面标签优先显示组合执行目标，真实持仓以 `AccountLedger(real)` 为准。

## 启用与回退

```powershell
python -m pip install -r backend/requirements.txt
python -m scripts.activate_ashare_allocation
```

也可使用 `uv sync --frozen` 安装锁定依赖。生产需要 CVXPY 1.7.5 / CLARABEL 0.11.1；当前 Windows Python 3.10 可运行，项目 `uv` 配置仍以 Python 3.13 为准。

启用命令先在 `data/backups/` 备份配置、因子状态、旧组合计划、窗口快照和 SQLite 在线备份，再生成双账户计划、设置本地 `ashare_allocation_model` 并清理旧 A 股操作卡片。它不执行真实或影子交易、不发邮件；重复运行沿用已生成计划。更新代码后须重启盘中监控和桌面窗口。收盘后生成的计划最早下个交易日 09:30 执行，周日新因子到生效时会替换对应目标版本。

回退：将本地 `jobs/market_monitor_config.json` 的 `ashare_allocation_model` 改成 `legacy`，重启监控/窗口；不删除或覆盖账本。没有此配置项时也可用环境变量 `INVEST_ASHARE_ALLOCATION_MODEL=legacy`，本地显式配置优先。不应恢复旧账户数据库来回退算法，否则会丢失之后录入的真实成交。

## 验证边界

此前冻结样本的 10 个月比较为 2025-12-30 至 2026-10-29：原生产核心回放 `+39.66%`、最大回撤 `-27.91%`；本方案 `+50.29%`、最大回撤 `-19.85%`。这是固定当前样本池的离线模拟，不是真实账户收益或未来承诺，存在样本选择偏差；超额收益置信区间跨零，不能证明稳定胜出。严格退出前四本身贡献了相当部分改善，不能把全部差异归功于正则项。

测试覆盖解析最优解、交易成本免交易区、预算/现金底线、零目标退出、点时协方差、周计划与重启、部分成交/手动卖出、数据失败、T+1/跌停、双账户与重复执行、后端不回退单股模型及请求无法伪造买单。实盘成交与券商净费用不在自动验证范围内。

2026-10-30 部署校验：20 项组合专项通过；其余回归 811 项通过、13 项按既有条件跳过。原全量测试中 `test_dreaming_verdict_source.py` 有 8 项因固定的 2026-05 样本超出当前回看窗口失败；该文件与 `jobs/dreaming.py` 未改动，单独将测试时钟固定回原样本日期后 15 项全部通过。上述 811 项回归显式排除了该历史日期文件，不能称为原样全量零失败。

另用 3 个历史时点、各 2 种虚拟持仓的相同输入对照冻结研究求解器，6 组目标权重最大绝对差 `0.00000264`。双账户生产计划均为 `optimal`，风险数据截止 2026-10-30，最早执行时点为 2026-11-02 09:30；启用和重启没有新增成交或改写持仓。
